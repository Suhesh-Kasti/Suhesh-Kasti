### 🧰 What I actually know

No percentage bars, because "85% at web exploitation" means nothing. Here's the honest version — click to expand.

<details>
<summary><b>Offensive security</b></summary>

Manual web testing with Burp Suite, and the usual suspects that actually show up: SQL injection, XSS, SSRF, authentication and JWT flaws, access control, file path traversal, SSTI, request smuggling, and logic bugs that no scanner will ever find. Around 200 PortSwigger Academy labs worked through, 100 written up on my site. Comfortable on Linux, happy in a terminal, decent with a little Python and Bash to glue things together.

</details>

<details>
<summary><b>F5 BIG-IP — ASM/WAF</b></summary>

Two and a half years of production WAF work: ASM policy build-out and tuning, handling false positives without turning the policy into Swiss cheese, signature management, virtual servers and pools, and being the person who gets asked why a legitimate request is suddenly getting blocked.

</details>

<details>
<summary><b>IT &amp; network administration</b></summary>

Windows and Linux administration, DNS (including DNSSEC — I care about it more than is normal), networking fundamentals, firewalls, and troubleshooting things end to end when the ticket just says "internet is down".

</details>

<details>
<summary><b>DevOps &amp; tooling</b></summary>

Docker daily — not an expert, but it's how I run things. Git and GitHub, a bit of scripting to avoid doing anything twice, Cisco Packet Tracer for lab networks, and enough cloud/cloudflare to host everything I build for free.

</details>

<details>
<summary><b>Clients &amp; communication</b></summary>

3+ years of customer-facing work, including the hard kind. I can explain a vulnerability to someone non-technical without either scaring them or overselling it — genuinely the skill I use most.

</details>

### ✍️ Why the site exists

Most people's security notes live in a folder nobody ever sees. I'd rather publish mine — partly because writing for an actual reader forces me to understand it properly, and partly because someone googling a specific PortSwigger lab at 2am deserves better than a blog post from 2016 that says "just use sqlmap".

The whole thing is open source, including the content pipeline. **[Have a look →](https://github.com/Suhesh-Kasti/suhesh)**
